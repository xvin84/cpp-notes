# Типы с плавающей точкой

> [!info] Не из лекции
> Собрано по темам лекции от 12.09.2026. Материалов лекции
> у ассистента не было, формулировки не преподавательские.

Тип с плавающей точкой (floating point type) хранит вещественное число как
мантиссу и показатель степени — отсюда и «плавающая» точка: одно и то же
количество бит обслуживает и 0.001, и 10¹⁵, но с разной абсолютной точностью.

| Тип | Обычно | Значащих десятичных цифр |
|---|---|---|
| `float` | 4 байта | ~7 |
| `double` | 8 байт | ~15–16 |
| `long double` | 10–16 байт | ~18–19 (зависит от платформы) |

По умолчанию берут `double`: у `float` точности хватает редко, а выигрыш
в памяти на одиночных переменных незаметен.

## Суффиксы литералов

```cpp
1.5     // double — по умолчанию
1.5f    // float
1.5L    // long double
```

Отсюда типичная нескладица: `double x = 0.0f;` — литерал сначала создаётся как
`float`, потом расширяется до `double`. Работает, но сообщает читателю неправду
о типе. Пишется просто `double x = 0.0;`.

## Точность — главное, что нужно помнить

Дробные значения хранятся в двоичной системе, и большинство привычных десятичных
дробей в ней непредставимы точно — как 1/3 непредставима в десятичной записи.

```cpp
#include <iomanip>
#include <iostream>

int main() {
  double sum = 0.1 + 0.2;
  std::cout << std::setprecision(17) << sum << '\n';  // 0.30000000000000004
  std::cout << (sum == 0.3) << '\n';                  // 0
  return 0;
}
```

Отсюда правило: **вещественные числа не сравнивают через `==`**. Сравнивают
модуль разности с допуском:

```cpp
#include <cmath>

constexpr double kEpsilon = 1e-9;
if (std::abs(a - b) < kEpsilon) {
  // считаем равными
}
```

Величина допуска — не универсальная константа: для чисел порядка миллиона
`1e-9` бессмысленно мал.

## Взаимодействие с целыми

Присваивание `double` в `int` отбрасывает дробную часть (усечение к нулю,
не округление) и требует явного [[static_cast]] — иначе компилятор справедливо
предупреждает о потере данных:

```cpp
double value = 2.9;
int truncated = static_cast<int>(value);   // 2, а не 3
```

Округление по правилам математики — `std::round`, `std::floor`, `std::ceil`
из `<cmath>`.

## Тонкости

- Деление на ноль здесь не роняет программу, как у [[Целочисленное деление и остаток|целых]]:
  при арифметике IEEE 754 получаются `inf` и `nan`. Стандарт C++ этого
  не гарантирует, но на учебных платформах будет именно так.
- `nan` не равен ничему, включая самого себя: `x != x` — способ его поймать.
- Сложение чисел очень разного порядка теряет младшие разряды: прибавить
  `1e-10` к `1e10` — всё равно что не прибавлять.
- Порядок сложения влияет на результат: `(a + b) + c` и `a + (b + c)` могут
  отличаться в последних разрядах.

## Частые ошибки

- `float` там, где нужна точность: накопленная ошибка вылезает уже
  на нескольких тысячах операций.
- Сравнение через `==` и удивление, почему условие не срабатывает.
- Ожидание, что `static_cast<int>` округлит, — он отбрасывает.
