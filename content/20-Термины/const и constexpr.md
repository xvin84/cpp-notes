# const и constexpr

> [!info] Конспект, а не материал курса
> Собрано по темам занятия от 12.09.2026, без опоры на официальные материалы.
> В спорном месте правы они, а не эта страница.

`const` — «после инициализации не меняется». `constexpr` — «значение известно
уже на этапе компиляции». Второе сильнее первого: всякая `constexpr`-переменная
является и `const`.

```cpp
const int size = ReadSize();       // значение узнаем во время работы, менять нельзя
constexpr int kMaxSize = 100;      // известно компилятору
```

## Зачем

**Читателю.** `const` у переменной сообщает: дальше по коду её значение
не изменится, можно не выискивать присваивания.

**Компилятору.** `constexpr` можно использовать там, где требуется константное
выражение: размер массива, параметр шаблона, `case` в `switch`.

```cpp
constexpr int kBufferSize = 256;
int buffer[kBufferSize];           // так можно
```

**Себе.** Именованная константа вместо числа посреди выражения — это ещё
и объяснение, что число означает:

```cpp
constexpr int kSecondsInHour = 3600;
int hours = total_seconds / kSecondsInHour;   // понятно без комментария
```

Такие «голые» числа называют магическими (magic numbers), и `clang-tidy`
на них ругается проверкой `readability-magic-numbers`. Исключение — 0 и 1.

## Именование

По [[Кодстайл курса|кодстайлу курса]] константы пишутся в `kCamelCase`:
`kMaxSize`, `kSecondsInMinute`, `kEpsilon`. Префикс `k` — от немецкого
*Konstante*, прижился через Google Style Guide. Правило распространяется
на глобальные константы, константы пространства имён и статические
константные поля класса.

## const-корректность

Привычка помечать `const` всё, что не меняется, называется const-correctness.
Проверка `misc-const-correctness` в `clang-tidy` предлагает добавить `const`
к переменным, которые вычисляются один раз:

```cpp
const int total_time = hours * kSecondsInHour + minutes * kSecondsInMinute;
```

Дальше по коду видно: это значение окончательное.

## Тонкости

- `const` у переменной не означает, что значение известно заранее: оно может
  прийти из `std::cin`.
- `constexpr` требует, чтобы инициализатор вычислялся компилятором, — вызов
  обычной функции туда не поставить.
- Для указателей важно, что именно константа: `const int* p` — нельзя менять
  значение по указателю, `int* const p` — нельзя менять сам указатель.
  Это отдельная тема, всплывёт вместе с указателями.
- `constexpr` бывает и у функций, тогда их можно вычислять на этапе компиляции.

## Частые ошибки

- Объявить константу без `k` и получить замечание на ревью.
- Магическое число «на один раз» — оно почти всегда встречается ещё раз,
  и тогда одно из мест забывают поправить.
- Ждать от `const` защиты от изменения через другой указатель или ссылку:
  `const` — договорённость, а не охрана памяти.
