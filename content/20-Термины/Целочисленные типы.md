Целочисленный тип (integer type) хранит целое число в фиксированном количестве
байт. Размер определяет диапазон: чем больше байт, тем шире диапазон и тем
больше памяти занимает переменная.

## Какие бывают

| Тип | Гарантия стандарта | Обычно на x86-64 Linux | Диапазон (типично) |
|---|---|---|---|
| `char` | ≥ 8 бит | 1 байт | −128…127 |
| `short` | ≥ 16 бит | 2 байта | −32 768…32 767 |
| `int` | ≥ 16 бит | 4 байта | −2 147 483 648…2 147 483 647 |
| `long` | ≥ 32 бита | 8 байт | ±9.2·10¹⁸ |
| `long long` | ≥ 64 бита | 8 байт | ±9.2·10¹⁸ |

Стандарт задаёт только минимумы, а не точные размеры: `long` на Windows —
4 байта, на Linux — 8. Полагаться на конкретное число байт нельзя, это
частый источник кода, который «работает только у меня».

Узнать фактические значения:

```cpp
#include <iostream>
#include <limits>

int main() {
  std::cout << sizeof(int) << '\n';                          // размер в байтах
  std::cout << std::numeric_limits<int>::max() << '\n';      // верхняя граница
  return 0;
}
```

Когда размер важен точно — есть типы фиксированной ширины из `<cstdint>`:
`int32_t`, `int64_t`, `uint8_t`. Они гарантируют ровно столько бит, сколько
написано в имени.

## Суффиксы литералов

У самого числа в коде тоже есть тип. По умолчанию целый литерал — `int`,
а если число в `int` не помещается, компилятор берёт следующий подходящий
тип. Суффикс задаёт тип явно:

```cpp
10     // int
10U    // unsigned int
10L    // long
10UL   // unsigned long
10LL   // long long
10ULL  // unsigned long long
```

Регистр значения не имеет, но `L` пишут заглавной: строчная `l` слишком похожа
на единицу.

Суффикс — не украшение, он меняет результат вычисления. Классический случай —
переполнение в промежуточном значении:

```cpp
long long a = 1000000 * 1000000;    // оба литерала int: переполнение
long long b = 1000000LL * 1000000;  // вычисление идёт в long long
```

В первой строке умножение выполняется в `int`, переполняется — и только потом
испорченный результат попадает в `long long`. Тип переменной слева на порядок
вычисления не влияет, важны типы операндов. Переполнение знакового целого —
[[Неопределённое поведение]], а не «просто отрицательное число».

## Тонкости

- Знаковость `char` не определена стандартом: на одних платформах он знаковый,
  на других нет. Для чисел используют `signed char` или `unsigned char`,
  а `char` оставляют для символов.
- `sizeof(char)` равен 1 по определению, но «1 байт» не обязан быть 8 битами
  (на учебных платформах — всегда 8).
- Диапазон несимметричен: отрицательных значений на одно больше, чем
  положительных, потому что ноль занимает место в положительной половине.

## Частые ошибки

- Считать, что `int` всегда 4 байта, а `long` — 8.
- Забыть суффикс при работе с большими числами и получить переполнение
  до присваивания.
- Использовать `int` для размеров и индексов больших контейнеров, где нужен
  64-битный тип.
