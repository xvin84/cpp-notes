# static_cast

> [!info] Не из лекции
> Собрано по темам лекции от 12.09.2026. Материалов лекции
> у ассистента не было, формулировки не преподавательские.

`static_cast<T>(value)` — явное преобразование значения к типу `T`, проверяемое
на этапе компиляции. Компилятор откажется, если преобразование бессмысленно.

```cpp
double value = 2.9;
int truncated = static_cast<int>(value);   // 2
```

## Зачем писать явно

Многие преобразования компилятор сделает и сам, молча. Проблема в том, что
часть из них теряет данные, и явная запись — способ сказать «я знаю, что делаю»:

```cpp
int total = 7;
int count = 2;

double wrong = total / count;                      // 3.0: делили целые
double right = static_cast<double>(total) / count; // 3.5
```

Во второй строке приведение меняет тип **до** деления, поэтому работает
вещественная арифметика. Это самое частое применение `static_cast` в учебных
задачах — см. [[Целочисленное деление и остаток]].

## Почему не в стиле C

Старая запись `(int)value` называется C-style cast и запрещена
[[Кодстайл курса|кодстайлом курса]]. Причина не в эстетике: C-style cast
последовательно пробует несколько разных преобразований, включая `const_cast`
и `reinterpret_cast`, и молча применяет первое подходящее. То есть одна и та же
запись может оказаться безобидным приведением числа, а может — снятием `const`
или переинтерпретацией памяти, и по коду не видно, что именно произошло.

`static_cast` умеет только безопасную часть и ломается на этапе компиляции,
если попросить лишнего. Плюс его легко найти поиском по коду, а `(int)` —
нет. Ещё `clang-tidy` ловит C-style cast проверкой `google-readability-casting`.

## Что происходит при сужении

- `double` → `int`: дробная часть отбрасывается, усечение к нулю
  (`static_cast<int>(-2.9)` даёт −2). Округление — `std::round` из `<cmath>`.
- Большое значение → более узкий целый тип: старшие биты теряются, результат
  для знаковых типов до C++20 был определён реализацией.
- `double` → `int`, когда значение не влезает в диапазон `int`:
  [[Неопределённое поведение]].

## Другие приведения

`static_cast` — один из четырёх именованных: `const_cast` снимает `const`,
`reinterpret_cast` переинтерпретирует биты, `dynamic_cast` проверяет тип
в иерархии классов во время выполнения. Три последних в начале курса не нужны;
появление `reinterpret_cast` в учебном коде почти всегда означает, что что-то
пошло не так.

## Частые ошибки

- `static_cast<double>(a / b)` вместо `static_cast<double>(a) / b`:
  приведение уже после целочисленного деления ничего не спасает.
- Ожидание округления вместо усечения.
- C-style cast по привычке из С — не пройдёт проверку `clang-tidy`.
