## 1. Из чего состоит программа

```cpp
#include <iostream>

int main() {
  std::cout << "Hello, world!\n";
  return 0;
}
```

Четыре вещи, которые стоит различать с самого начала:

- `#include <iostream>` — директива препроцессора: содержимое заголовка
  подставляется в файл **до** компиляции. Подробности — [[Подключение заголовков]].
- `int main()` — точка входа. Именно её вызывает система при запуске, и она
  обязана возвращать `int`.
- `std::` — квалификатор пространства имён. Всё из стандартной библиотеки живёт
  в `std`, и писать это явно — требование [[Кодстайл курса|кодстайла]].
  `using namespace std;` в заголовочных файлах запрещён, в задачах — нежелателен:
  он вываливает в глобальную область тысячи имён.
- `return 0;` — код возврата, ноль означает «успех». Для `main` его можно
  опустить, компилятор подставит сам, но привычка писать явно полезна.

Сборка и запуск:

```sh
g++ main.cpp -o main && ./main
```

`-o main` задаёт имя результата, `&&` запускает программу только если сборка
удалась. Про другие компиляторы, стадии сборки и флаги — [[Компиляция и сборка]].

## 2. Переменные

Объявление выделяет память, инициализация задаёт первое значение. В C++ это
разные действия, и пропустить второе — распространённая беда:

```cpp
int count = 0;      // так
int count;          // значение неопределённое, читать нельзя
```

Чтение неинициализированной переменной — [[Неопределённое поведение]].
Программа при этом обычно «работает», и именно поэтому ошибка живучая.
Подробнее — [[Инициализация переменных]].

Правило кодстайла: одна переменная на строку, имя в `snake_case`.

## 3. Типы данных

Тип определяет, сколько памяти занимает значение и как оно интерпретируется.

```cpp
#include <iostream>

int main() {
  int count = 42;
  double weight = 3.5;
  unsigned int flags = 0U;
  long long big = 10'000'000'000LL;

  std::cout << "int: " << sizeof(count) << " байт\n";         // 4
  std::cout << "double: " << sizeof(weight) << " байт\n";     // 8
  std::cout << "unsigned: " << sizeof(flags) << " байт\n";    // 4
  std::cout << "long long: " << sizeof(big) << " байт\n";     // 8
  return 0;
}
```

Числа справа — то, что получается на x86-64 Linux. Стандарт задаёт только
минимальные размеры, поэтому `sizeof(long)` на Windows и Linux отличается.
Разбор по группам — [[Целочисленные типы]], [[Беззнаковые типы]],
[[Типы с плавающей точкой]].

Апостроф внутри числа (`10'000'000'000`) — разделитель разрядов, появился
в C++14. На значение не влияет, читается лучше.

### Суффиксы литералов

У числа в коде тоже есть тип, и суффикс задаёт его явно:

```cpp
10     // int              1.5    // double
10U    // unsigned int     1.5f   // float
10L    // long             1.5L   // long double
10LL   // long long
10UL   // unsigned long
10ULL  // unsigned long long
```

Это не косметика. Выражение вычисляется в типах операндов, а не в типе
переменной слева:

```cpp
long long a = 1000000 * 1000000;    // переполнение int: -727379968
long long b = 1000000LL * 1000000;  // 1000000000000
```

В первой строке умножение идёт в `int`, переполняется — и в `long long`
попадает уже испорченное значение. Компилятор с `-Wall` предупреждает:
`integer overflow in expression of type 'int'`.

### Беззнаковые

`unsigned` хранит только неотрицательные числа и при переполнении не ломается,
а заворачивается по модулю 2ⁿ:

```cpp
unsigned int x = 0;
std::cout << x - 1 << '\n';   // 4294967295, а не -1
```

Отсюда бесконечный цикл `for (unsigned i = n; i >= 0; --i)` и перевёрнутые
сравнения при смешивании со знаковыми. Подробно — [[Беззнаковые типы]].

## 4. Константы

Число посреди выражения ничего не говорит читателю. Именованная константа
говорит:

```cpp
constexpr int kSecondsInHour = 3600;
const int hours = total_seconds / kSecondsInHour;
```

`const` — «не изменится после инициализации», `constexpr` — «известно
на этапе компиляции». Имена констант по кодстайлу — `kCamelCase`.
Подробнее — [[const и constexpr]].

## 5. Арифметика

Главная ловушка лекции: если оба операнда целые, то и деление целое.

```cpp
#include <iostream>

int main() {
  int apples = 0;
  int baskets = 0;
  std::cin >> apples >> baskets;

  const int per_basket = apples / baskets;                      // 17 / 5 = 3
  const int left_over = apples % baskets;                       // 17 % 5 = 2
  const double exact = static_cast<double>(apples) / baskets;   // 3.4

  std::cout << "в каждой: " << per_basket << '\n';
  std::cout << "осталось: " << left_over << '\n';
  std::cout << "точно: " << exact << '\n';
  return 0;
}
```

Приведение обязано стоять **до** деления: `static_cast<double>(apples / baskets)`
не спасёт, там уже потеряна дробная часть. См. [[static_cast]].

На отрицательных числах деление усекает к нулю, а знак остатка берётся
от делимого: `-7 / 2` даёт −3, `-7 % 2` даёт −1. Деление целого на ноль —
[[Неопределённое поведение]], у вещественных вместо этого получаются `inf`
и `nan`. Приёмы вроде округления вверх и приведения остатка в неотрицательный
диапазон — в [[Целочисленное деление и остаток]].

Вещественные числа хранятся неточно:

```cpp
std::cout << (0.1 + 0.2 == 0.3) << '\n';   // 0
```

Поэтому их не сравнивают через `==`, а сравнивают модуль разности с допуском.
См. [[Типы с плавающей точкой]].

## 6. Ввод и вывод

`std::cin` читает, `std::cout` печатает, `>>` и `<<` выстраиваются цепочкой.
Оператор `>>` пропускает пробелы и переводы строк, поэтому для него
`17 5` и `17\n5` — одно и то же.

Печатать перевод строки лучше через `'\n'`: `std::endl` дополнительно
сбрасывает буфер, и в цикле это заметно медленнее. Подробности —
[[Потоки ввода и вывода]].

Ширина поля и заполнитель — из `<iomanip>`:

```cpp
#include <iomanip>
#include <iostream>

int main() {
  constexpr double kPi = 3.14159265358979;

  std::cout << std::fixed << std::setprecision(4) << kPi << '\n';   // 3.1416
  std::cout << std::setfill('.') << std::setw(12) << "итого" << 100 << '\n';
  return 0;
}
```

`std::setw` действует ровно на один следующий вывод, остальные манипуляторы
липкие. Разбор — [[Форматирование вывода]].

## Грабли

- **`setw` считает байты, а не символы.** Вторая строка примера выше печатает
  `..итого100`: слово «итого» в UTF-8 занимает 10 байт, до ширины 12 остаётся
  два символа-заполнителя. С латиницей то же самое выглядело бы как семь точек.
  Выравнивать таблицы с кириллицей через `setw` бессмысленно.
- **`double x = 0.0f;`** — литерал создаётся как `float` и расширяется
  до `double`. Работает, но сообщает читателю неправду о типе.
- **`static_cast<int>` не округляет, а отбрасывает** дробную часть, причём
  в сторону нуля: из −2.9 получается −2.
- **`int y{3.9};` не компилируется** — списочная инициализация запрещает
  сужение, в отличие от `int y = 3.9;`. Это не недостаток, а защита.
- **Компилятор знает больше, чем говорит по умолчанию.** Переполнение
  литералов, сравнение знакового с беззнаковым, неиспользуемая переменная —
  всё это видно, если добавить `-Wall -Wextra` к команде сборки. Полезно,
  когда программа ведёт себя не так, как задумано.
